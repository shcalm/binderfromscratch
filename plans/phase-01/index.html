    第一阶段执行计划¶

    全项目状态统一维护在任务总表；本文保留第一阶段的实施说明，下面的勾选记录为建立总表时的阶段快照。

    目标：建立从普通 C 函数到自研字符设备 RPC 的教学闭环，同时用实验和 Android 对照解释每一次设计选择。

    架构：先用用户态程序暴露进程边界和协议需求，再在 QEMU 中演进驱动。早期只支持固定服务端；对象寻址、多线程和映射按需求逐章引入。

    工具：C11、Make、Python unittest、strace、QEMU、固定 Linux 内核与配置；正文使用 Markdown。

    A. 教学规范和入门反例¶

    • [x] docs/design/teaching-contract.md 记录设计推导、实验、Android 对照的完成标准。
    • [x] docs/plans/roadmap.md 为全部 22 章列出问题、实验、源码对照和阶段门槛。
    • [x] examples/intro/local_add.c 展示本地调用。
    • [x] examples/intro/fork_private.c 用等待子进程完成排除“还没计算完”的解释。
    • [x] examples/intro/socket_rpc.c 实现定长消息、字节序、远端错误、服务端提前退出。
    • [x] tests/test_intro.py 覆盖正常结果、不同 PID、输入范围、溢出和退出；每次子进程测试限时五秒。
    • [x] docs/chapters/p01-process.md 与 01-why-binder.md 给出实验推导初稿。
    • [x] docs/reference/android-binder.md 记录已核查的 v6.6 驱动入口与对照限制。

    验收命令：make test；输出应为七组测试通过。strace -f 应能观察两个 PID 的发送与接收。本阶段不宣称具备独立进程服务发现、驱动 RPC 或生产超时机制。

    B. 补齐预备篇与隔离实验环境¶

    • [ ] 完成 P01 线程共享示例，解释共享地址空间与同步的区别；用同步原语消除数据竞争。
    • [ ] 编写 P02，基于现有 Socket 跟踪解释系统调用、阻塞与错误返回。
    • [ ] 新建 tools/kernel/manifest.md、tools/kernel/config，固定内核提交/归档校验值、编译工具与配置。
    • [ ] 新建 tools/qemu/ 构建和启动脚本：准备最小 rootfs、串口输出、非 root 宿主启动与测试超时；不挂载宿主可写目录。
    • [ ] 编写 P03 最小模块和失败初始化实验；在 VM 中验证加载/卸载及日志。
    • [ ] 编写 P04，从干净构建目录复现启动，记录镜像来源、构建命令、模块版本匹配和故障恢复。

    验收：VM 启动到测试入口；加载模块后出现带实验标识的 init 日志；卸载出现 exit 日志；失败初始化不留下设备或分配资源。宿主只负责构建和启动 QEMU。

    C. 第 02 章：受控内核入口¶

    • [ ] 先写 docs/design/device-abi.md：比较 read/write 和 ioctl，规定打开上下文、命令版本、字段宽度、错误码及所有权。
    • [ ] 新建 include/uapi/mini_binder.h、driver/mini_binder.c、driver/Makefile；使用 miscdevice 简化设备注册，并解释其与字符设备/VFS 的关系。
    • [ ] 新建 tests/kernel/device_test.c：打开/关闭、未知 ioctl、无效用户指针、错误长度和重复操作。
    • [ ] 实现最小查询命令；用户输入校验和关闭回收先于功能扩展。
    • [ ] 编写第 02 章，对照 binder_open/binder_ioctl；明确 ioctl 是入口而不是完整 RPC 语义。

    验收：VM 内正常查询成功，非法命令与用户指针返回约定错误；循环打开关闭后资源计数恢复；内核日志无告警。

    D. 第 03 章：最小同步 RPC¶

    • [ ] 先写 docs/design/minimal-rpc.md：一服务端、多客户端、每客户端一笔进行中调用；规定注册、提交、领取、回复及关闭协议。
    • [ ] 比较忙轮询与等待队列；设计显式条件，等待在循环中重新检查条件，解释丢失唤醒风险。
    • [ ] 定义请求所有权及排队/领取/完成/失败状态；设计服务端退出和客户端中断的终结规则。
    • [ ] 编写 userspace/add_server.c、userspace/add_client.c 与 VM 验收测试，再实现驱动中的队列和等待逻辑。
    • [ ] 实现请求关联和回复者校验，拒绝未知或重复回复；定义部分成功后错误返回时的资源归属。
    • [ ] 编写第 03 章，对照真实 Binder 的工作交付，明确此时尚无对象网络与嵌套事务。

    验收：多个客户端返回各自结果；无服务端有确定错误；服务端在领取前后退出都能结束受影响的调用；客户端等待中被信号中断不遗留请求；伪造与重复回复被拒绝。测试设截止时间，超时视为失败，不算取消协议的证明。

    E. M1 发布¶

    • [ ] 完成 P01–P04、第 01–03 章的三项规范复核及干净环境重放。
    • [ ] 接入 Markdown 网站和链接检查；图示与文档均能在无交互模式阅读。
    • [ ] 记录验证环境、测试输出、已知限制；建立章节代码索引并发布阶段标签。

    后续阶段的接口必须在相应设计问题展开后确定，不在这里提前塞入 Node、Ref、线程池等最终结构。
