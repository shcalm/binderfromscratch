# 修订、勘误与 ABI 变更

## 工作规则

报告问题时提供章节、代码提交/标签、运行清单、命令、预期与实际结果。内核问题附完整 VM 日志，不以末尾一行代替；外部资料的版本变化与本项目错误分别记录。

文字修订保留设计结论的来由；如果实验推翻旧结论，同时修订正文、测试和限制说明。不能只改测试使其通过。ABI 变化先记录兼容影响，再调整驱动、用户态和实验；需要新命令时不悄悄改变旧命令布局。

开发快照使用 Git 提交追溯。正式章节发布采用不可移动标签，例如 `chapter-03-v1`；修复发布 `chapter-03-v2`，旧标签仍可复现。重写历史或移动标签会破坏教学对照，不能替代迁移说明。

任务状态统一更新[总表](../plans/task-backlog.md)。阶段报告记录完整性边界；一次测试通过不等于全章发布，也不等于所有并发路径被覆盖。

## 已发现并修正的问题

| 问题 | 原因与修正 | 回归证据 |
| --- | --- | --- |
| 无回复实验就绪半行可能无限等待 | select 只保证可读，不保证整行；改成带单调截止的逐块读取 | `test_partial_readiness_line_times_out_and_cleans_up` |
| 取消 CALL 后可能自动重发 | 原样返回 ERESTARTSYS 允许 SA_RESTART 重启 ioctl；取消路径转为 EINTR | VM 中已交付请求 + SA_RESTART + 信号；验证无新请求、迟到回复 ENOENT |
| 回复事件在信号退出时可能丢日志 | 重定向 stdout 是缓冲输出而处理器 _exit 不刷新；正常回复后显式 fflush | VM demo 的三条 event=replied 日志，阶段报告注明日志不是持久化提交记录 |

完整运行条件见[阶段报告](../reports/m0-m1-progress.md)。未实施的功能不在这里写成修复完成。
