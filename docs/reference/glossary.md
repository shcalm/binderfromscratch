# 术语表

本表固定本书中英文用词，帮助区分 Linux 概念、真实 Binder 协议和教学模型。概念对应不表示 mini-binder 已实现或兼容该机制；当前能力以[任务总表](../plans/task-backlog.md)和对应实验为准。涉及真实实现时遵守[源码阅读基线](android-binder.md)，驱动目前以 Linux v6.6 为阅读基线，AOSP 用户态尚需另行锁定。

## 执行与地址空间

| 中文用词 | 英文/常用符号 | 本书含义与易混点 |
| --- | --- | --- |
| 进程 | process | 操作系统组织执行与资源的上下文。普通 `fork()` 示例中的父子进程有独立虚拟地址空间；不能从一个地址数值相同推导访问的是同一份数据。Linux 的具体资源共享还取决于创建方式，不将 PID 当成全部资源关系。 |
| 线程 | thread | 执行流；同进程线程通常共享地址空间和文件描述符表，但有各自执行状态。共享变量不意味着无须同步，数据竞争不是正确的共享演示。 |
| 用户态/内核态 | user mode / kernel mode | CPU 执行权限与执行环境的区分。系统调用进入内核不必然切换到另一个进程；调度切换、权限级切换是不同事件。 |
| 虚拟地址/用户指针 | virtual address / user pointer | 地址在对应地址空间内解释。内核收到的用户地址不可信，必须通过适当用户访问接口处理；范围检查不保证后续访问不会失败。地址也不是跨进程对象身份。 |
| 系统调用 | system call | 用户态请求内核服务的入口；库函数可能封装系统调用，也可能完全在用户态完成。成功后不能仅凭旧的 `errno` 判断失败。 |
| 设备协议/ABI | device protocol / application binary interface | 用户态与驱动约定的命令、布局和行为。`ioctl` 提供调用入口，不自动提供事务、对象、授权或 RPC 语义。mini-binder 采用独立教学 ABI。 |

## 文件、通信上下文与工作

| 中文用词 | 英文/常用符号 | 本书含义与易混点 |
| --- | --- | --- |
| 文件描述符 | file descriptor / fd | 文件描述符表中的整数索引；通常用于描述进程中的文件入口，线程可共享该表。相同数字在不同表中可能指向不同打开文件对象，不能靠发送整数完成文件传递。 |
| 打开文件对象 | open file description / `struct file` | 一次打开所建立的内核文件状态。`dup()` 和通常的 `fork()` 继承可让多个 fd 持有同一对象；关闭一个 fd 不一定触发最终 `release`。文件内容、fd 数字和该对象不是同一事物。 |
| Binder 通信上下文 | Binder open context / `binder_proc` | 驱动为打开 Binder 设备建立的通信状态，组织引用、线程等资源。不能机械等同于“一 PID 恰好一个对象”；重复打开、继承、设备及具体版本限制需查实际路径。 |
| Binder 域/设备上下文 | Binder context / device context | 某 Binder 设备所服务的通信域及其 Context Manager 等状态。与某次打开对应的 `binder_proc` 不同；不同域的句柄不能按同一命名空间解释。不要用无修饰的“上下文”混指二者。 |
| Binder 线程状态 | `binder_thread` | 驱动记录的通信线程状态，包括线程相关待办和同步调用关系等。不是内核替应用创建的业务线程；用户线程池的创建和方法执行属于用户态。 |
| 消息 | message | 本书对协议传输单元的泛称。消息可以携带请求、回复或控制事件；没有声明关联、顺序与完成规则的“发消息”不等于完整 RPC。 |
| 事务 | transaction / `binder_transaction` | 按上下文指一次请求/回复传输，或驱动记录的一次事务工作；若指整个业务调用，正文明确写“同步调用”。一个同步调用涉及请求和回复，不把它们强行看作一个永不变化的内核结构。 |
| 同步调用 | synchronous call / synchronous RPC | 调用者等待业务回复或约定失败的调用关系。等待被信号中断、测试超时、取消工作、对端退出是不同事件，需分别规定语义。 |
| 工作项/待办队列 | work item / todo queue | 驱动或用户态等待处理的工作及其容器；可能是事务，也可能是引用或死亡通知等控制工作。“队列非空”不等于业务已执行。 |
| 提交完成通知 | `BR_TRANSACTION_COMPLETE` | 驱动协议中的完成事件，不是服务方法返回值，也不能据此断言远端业务成功；同步业务回复通过 `BR_REPLY` 等对应路径交付。具体时点依命令、事务类型和版本核查。 |
| 单向调用 | oneway / `TF_ONE_WAY` | 不为该业务请求等待普通同步回复的语义；仍有提交、缓冲、队列、顺序、背压和失败成本。不是免费、无限容量或“不用驱动处理完成事件”。 |

## 对象、引用与发现

统一保留 `Node`、`Ref`、`Handle` 的英文写法；首次出现可写“对象节点（Node）”“远程引用记录（Ref）”“引用句柄（Handle）”。不要将三者统称为“对象 ID”。

| 中文用词 | 英文/常用符号 | 本书含义与易混点 |
| --- | --- | --- |
| 本地对象 | local Binder object | 实现业务方法的用户态对象。驱动负责路由和协议，不直接执行用户指针指向的方法；对象语言层生命周期还依赖用户态实现。 |
| 对象节点 | Node / `binder_node` | 驱动对某拥有者发布的本地 Binder 对象的身份及通信状态的表示。Node 不是对象业务数据的拷贝；相关驱动记录可能为清理/死亡引用继续存在，不意味着拥有者进程还活着。 |
| 远程引用记录 | Ref / `binder_ref` | 持有者通信上下文中指向 Node 的驱动记录，带有该上下文的描述符和引用状态。多个持有者可引用同一 Node；不能将发送方的 Ref 记录直接搬给接收方。 |
| 引用句柄 | Handle / descriptor | 在持有者通信上下文中查找远程引用的整数。相同数字在不同上下文可指不同对象，不同数字可指同一 Node；可复用，不能作为全局永久对象身份。也不是文件 fd。 |
| 对象描述符与转换 | Binder object descriptor / translation | 事务特殊对象元数据，例如本地对象或 Handle 表示。跨上下文传递时驱动需要解析并建立接收方表示；接收方若是对象拥有者还可能恢复本地对象表示，不能只复制整数。 |
| 本地对象标识与回传信息 | `ptr` / `cookie` | 真实 Binder 本地对象描述符中的不透明用户态值，用于身份关联或交付用户态；具体用途按字段与版本核查。驱动不把它们当可直接调用的业务函数，也不把原始地址当跨进程可用指针。 |
| 强引用 | strong reference | 表达持有存活对象的引用意图。驱动协议状态、libbinder 强引用及语言对象生命周期是不同层，需要协作；持有强引用不能阻止服务进程被终止。 |
| 弱引用 | weak reference | 允许记录对象身份并尝试获得可用强引用的引用形式，不保证业务对象仍可调用。用户态弱引用与驱动 `INCREFS` 等协议不能仅凭“弱”字视为完全等价；提升规则和失败条件须单独说明。 |
| 引用计数 | reference count / refcount | 对特定资源的持有数量及回收机制。必须说明计数对象与持有方；非零不必然表示进程活着，归零也不意味着所有相关记录同步消失，循环引用亦不会自动消除。 |
| 死亡通知 | death notification | 观察远端 Binder 对象相关死亡状态的协议，包含注册、取消、交付和确认等关系。不是通用健康检查，不保证业务正常或固定通知时延；具体竞态与支持边界需实验。 |
| 上下文管理者 | Context Manager | 某 Binder 域的引导对象角色，解决尚未取得普通对象引用时如何访问首个管理者的问题。句柄 0 有引导意义，需按该域及版本解释，不能推广成全局服务名数据库。 |
| 服务管理器 | ServiceManager / servicemanager | 用户态服务注册与查询组件，管理名称到 Binder 对象引用的关系，并承担相应策略。与驱动中的 Context Manager 角色有协作，但名称解析不由驱动完成；也不等于 Android 的 init。 |

## 数据、映射与控制

| 中文用词 | 英文/常用符号 | 本书含义与易混点 |
| --- | --- | --- |
| 数据容器 | Parcel | 用户态组织数据与特殊对象描述的容器；普通业务字段的编解码属于库/业务代码。驱动按协议处理对象/FD 元数据，不理解所有 Parcel 业务内容。教学格式不是 Android Parcel 兼容实现。 |
| 接收缓冲区 | receive buffer / Binder buffer | 接收方分配域中承载事务数据的一块资源，有独立分配、交付和释放责任。收到回复、事务结束、发送方退出不自动等于接收方已经释放缓冲区。 |
| 内存映射 | memory mapping / `mmap` | 在地址空间中建立虚拟内存区域与后备资源的关系，不等于一次性分配全部物理页，也不等于事务缓冲区分配。教学接收区设计应明确映射权限和页生命周期。 |
| 虚拟内存区域 | virtual memory area / VMA | 内核描述一段映射范围及权限等属性的对象。关闭原始 fd 后映射可继续存活，`close()`、`munmap()`、文件最终释放和进程退出必须分别分析。 |
| 复制次数 | copy count | 针对指定数据路径统计的实际字节搬运点。映射接收不表示发送到接收区不再复制，控制元数据也可能另有复制；须说明计数对象，不能仅靠耗时反推。 |
| 文件引用传递 | FD passing | 从发送者取得文件引用，在接收者表中建立 fd 的操作；接收整数可能不同，共享的是打开文件状态，不是复制文件内容。获取、预留、安装和失败释放分别有责任。 |
| 调用者身份/授权 | caller identity / authorization | 身份来自约定的可信凭据采集路径；payload 内自报 UID 不可信。授权决定能否转交对象/文件或调用方法，拥有可用 Handle 不自动满足业务权限。 |
| 阻塞、唤醒与取消 | blocking / wakeup / cancellation | 阻塞等待条件，唤醒促使重新检查条件，取消改变工作的后续执行责任。唤醒不保证条件永久成立；中断等待不自动撤销已经交付的工作。 |
| 截止时间/超时 | deadline / timeout | 实验运行器截止时间用于检测卡住；RPC 超时协议规定返回与在途工作处理。前者不能证明后者已实现，超时也不证明对端未执行。 |

新增术语时，先说明在哪一层使用，再补充有效域和易混概念。章节如采用更窄的教学定义，应当场标明，避免悄悄改变本表用词。
