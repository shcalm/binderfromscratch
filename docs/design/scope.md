# 范围与非目标

## 本项目要交付什么

《从零设计 Binder》面向掌握基本 C 的读者，使用普通 C 模型和逐步演进的 mini-binder 驱动，解释需求如何产生机制、为什么选择某方案、它新增了什么成本，以及怎样用实验检验。Android Binder 是带版本边界的真实系统对照。

全书规划为 4 章预备篇和 18 章正文，范围和门槛见[路线图](../plans/roadmap.md)；实际完成状态以[任务总表](../plans/task-backlog.md)和可定位证据为准。规划中的 Node、Ref、映射、FD、死亡通知、线程模型、安全策略等不能在对应实现和验收前称为已支持。

## 教学实现与执行环境

| 项目 | 首版约定 | 边界与理由 |
| --- | --- | --- |
| 架构 | Linux x86_64，C 驱动和用户态库/程序 | 先控制布局、工具链与调试变量；不宣称其他架构或 32 位进程已支持。 |
| 执行位置 | 内核模块在隔离 QEMU 实验 VM 中运行，宿主负责构建和启动 | 内核故障可能破坏整个运行实例；统一可恢复环境也是实验复现的一部分。不以宿主加载模块作为教程必经步骤。 |
| 运行基线 | 由环境清单固定源码、配置、编译器、rootfs 与产物校验值，并以实际验收为准 | 当前源码阅读基线不能自动充当已通过构建和启动的运行基线；KVM/软件模拟也分别验证。 |
| 设备与协议 | mini-binder 自有设备与教学 ABI；与真实 Binder 实验明确隔离 | 不是 `/dev/binder` 的替换实现，不把相似命令名称当作兼容性证据。具体命令、布局及版本在相应设计文档中决定。 |
| 演进方式 | 先固定服务端最小 RPC，再按需求加入数据、事务、对象、线程与生命周期 | 不在第一版预塞最终架构；各阶段仍要处理当时已经存在的非法输入、部分失败和退出。 |
| 发布方式 | 主线演进，正式章节使用不可移动标签；修订发布新标签 | 目前开发快照不能冒充已验收章节版本；ABI 变化需要理由、前后 diff 和实验迁移说明。 |

本页是范围约定，不是环境已完成声明。具体能运行哪些命令、在哪个镜像验证过，必须由对应清单与报告证明。

## 与 Android 的对应范围

当前驱动阅读基线为上游 Linux **v6.6** 的 Binder 驱动和 UAPI，见[源码阅读基线](../reference/android-binder.md)。这是源码定位选择，既不代表所有 Android 设备的内核，也不意味着已覆盖该标签全部代码路径。

| 层次 | 本书如何使用 | 不能据此声称什么 |
| --- | --- | --- |
| Linux Binder 驱动/UAPI | 为本章问题核查事务、队列、对象/FD 转换、映射、引用与身份相关路径 | 看过一个入口不能声称完整语义等价；厂商补丁、不同内核和配置可能改变行为。 |
| AOSP libbinder / Parcel | 进入对应章节时另锁标签或提交，核查序列化、代理、对象生命周期和线程协作 | Linux v6.6 不固定用户态版本；未选定 AOSP 版本时不添加伪精确源码行号。 |
| servicemanager | 对照引导对象、服务发现及用户态策略；与驱动 Context Manager 分开解释 | 教学注册表不能自动替代 Android 服务管理器及其权限、隔离和生命周期语义。 |
| Android 设备端到端运行 | 只有固定设备/镜像、内核、用户态及实际报告后才可报告结果 | 概念图或 VM 中 mini-binder 成功，不能证明 Android 应用可直接使用它。 |
| Rust Binder 实现 | 第 18 章在指定仓库、提交及集成状态下讨论语言与架构差异 | 不预设某实现已经合入、生产成熟或兼容所有 C 实现功能。 |

每章对应表应写出教学问题、教学机制、真实源码入口、相同点、差异和版本。驱动不替用户态解释全部业务数据、创建业务线程或按服务名分发方法。

## 不承诺的兼容与生产能力

下表区分全书内的教学简化与目前延后事项。以后若改变范围，先给出需求、设计、证据与迁移方式，不能只修改“支持”字样。

| 能力 | 当前范围决定 | 原因及重新考虑条件 |
| --- | --- | --- |
| Android libbinder/Parcel/UAPI 二进制兼容 | 首版不实现；教学 ABI 不兼容 libbinder | 兼容需要精确覆盖命令、布局、对象转换、错误、生命周期及历史行为，易掩盖初学者要理解的核心设计。不能拿现有 Android 程序直接验证教学 ABI。 |
| AIDL 编译器与完整代理代码生成 | 暂不实现，先手写小规模用户态接口 | 先让读者看见协议和分发责任；代码生成若成为独立需求，应另有格式和版本设计。 |
| 全部 Binder 特性及优化 | 仅覆盖各章实际论证、实现和验收的子集 | 不以真实驱动命令清单作为功能完成清单；未实现对象类型/标志应明确拒绝。具体扩展需新场景和实验。 |
| 多架构、32/64 位兼容、跨版本长期 ABI | 首版延后 | 指针表示、对齐、兼容入口与迁移需要独立验收。使用定宽字段只是设计基础，不等于已经兼容。 |
| Android 完整部署与管理域 | 不提供平台替换、完整多域部署、应用框架集成 | 设备命名、binderfs、容器/命名空间、管理器和启动策略均有独立边界；在阅读中遇到时解释，不假装教学单域覆盖所有部署。 |
| 完整 SELinux/LSM 与平台权限体系 | 第 13 章做最小威胁模型和明确访问策略；不复刻整个平台策略 | 可信身份、对象/FD 转交和方法授权要从最小实现开始；完整策略需要目标平台、策略版本及攻击面审计。 |
| 生产级实时性、优先级继承及调度保障 | 不作首版保证 | 演示有限嵌套路由不证明所有死锁都消除；调度策略和最坏时延需要更完整模型与环境证据。 |
| 通用 RPC 超时、取消与业务恰好执行一次 | 不作为默认保证；各阶段单独定义中断和退出语义 | 工作可能已执行但回复丢失，终结一次不等于业务副作用恰好一次；测试截止时间不构成取消协议。 |
| 无界负载、自动容错和透明重启 | 不实现无界队列或生产容错承诺 | 队列必须有界且耗尽行为明确；死亡通知不等于故障恢复，旧 Handle 与对象身份的重建需另行协议。 |
| 跨主机通信 | 不在本书范围 | 本地地址空间、文件引用、身份和生命周期不能直接推广到网络；网络 RPC 有额外失败与安全模型。 |
| DMA-BUF 分配器、设备同步完整栈 | 第 11 章解释 FD 传递与应用关系；有可用导出器才提供实测 | 传递 fd 不替代缓冲区分配、设备访问权限、缓存一致性或 fence 同步；不自制分配器凑演示。 |
| 与真实 Binder 等价的性能或安全性 | 不承诺 | 需匹配工作负载、内核/配置、用户态与长期审计；一次吞吐或压力结果不能证明等价。 |

## 教学简化不能豁免的正确性

教学版不承诺生产安全性，但不以此允许已知内存破坏、越权或无人回收资源。从第一条设备命令开始验证输入和用户指针，从第一个队列开始定义请求持有和终结责任，从第一段映射开始区分文件与 VMA 生命周期。

每次引入资源，立即规定正常完成、部分失败、信号中断、关闭和进程退出的责任；每次引入共享状态，立即规定同步、保活和竞争语义。第 12、13、15 章用于深化生命周期、安全和并发，不能作为把早期已知缺陷延期到最后的理由。

不支持的用法必须可辨认：明确拒绝，或在可验证的前置约束下限制实验。不能默认恶意输入不会出现，也不能用“不崩溃”代替资源和状态检查。

## 证据与结论的界限

- 普通 C 模型检验抽象关系，不证明内核指针、锁、并发或退出实现正确。
- 源码阅读说明指定版本路径与语义，不证明教学代码遵循了它，也不代表未核查版本。
- VM 功能实验只证明报告中的输入和调度路径；调试工具无告警不能证明没有所有内存错误。
- 复制点分析、资源计数和性能测量回答不同问题；吞吐提升不单独证明复制减少。
- 宿主截止时间发现卡住，不能证明 RPC 已取消；引用存在不能证明远端进程存活。

章节发布需要设计推导、可复现实验和版本化 Android 对照三者同时成立。局限必须随对应版本公开，计划、初稿和通过验收的能力分开记录。
