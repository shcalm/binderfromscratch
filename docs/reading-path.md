# 全书阅读顺序与 review 入口

全书的 P01–P04 和第 01–18 章均有正文。**第 09–18 章是本轮补齐、供集中 review 的设计与源码阅读稿；mini-binder 的实际实现仍到第 08 章。** 阅读后续设计时，不需要先运行一个尚不存在的新版本驱动；文中会把可以运行的普通程序、基于固定源码的结论、尚需实现的协议推演分别说明。

建议从[第 09 章](chapters/09-service-manager.md)开始顺序阅读。每次只抓住一个问题：上一版哪里不够，新办法怎样改变行为，又由谁承担新资源的回收责任？完整实现任务和正式发布门槛仍见[任务总表](plans/task-backlog.md)，本轮文档验证见[阅读稿报告](reports/remaining-chapters-draft.md)。

## review 时重点看什么

1. 开头是否能说清谁在做什么、遇到什么限制，读者是否知道接下来准备做哪些实验或推演。
2. 每个新术语是否在需要它的时候解释；只懂基本 C 的读者能否跟上核心例子。
3. 方案比较是否合理；被放弃的办法在什么条件下仍然适合，选定办法又增加了哪些成本。
4. 成功、失败和退出时，缓冲区、对象引用、文件与工作项各由谁释放，是否有说不清的责任。
5. 源码结论、实验结果和设计预期是否容易区分；后续设计有没有把前章未实现的能力写成现成工具。

可以按章号和小节标题反馈，例如“第 10 章回调例子中，A 的哪个线程还在运行不清楚”。本轮正文完成后再统一修改；正式实验实现和发布仍按[教学规范](design/teaching-contract.md)逐项推进。
