# 全书内容与实现路线

逐项执行与完成状态见[全项目任务总表](task-backlog.md)。本页保留章节演进和阶段依赖说明。

## 工作方式

按阶段验证代码可行性，再依照问题发生的顺序编写正文。每个章节完成设计、实验、Android 对照三项后才可发布。以下是计划，不表示对应代码已经实现。

先做贯通的最小 RPC，再扩展数据、事务、对象、并发和生命周期。普通 C 模型可以独立，但驱动必须从前一版连续演进，不能每章重新起炉灶。

## 逐章设计问题与实验

| 章 | 设计主问题与比较 | 关键实验和通过条件 | Android 对照方向 |
| --- | --- | --- | --- |
| P01 进程 | 地址相同是否意味着同一份数据？进程和线程的边界是什么？ | fork 后子进程写入，父进程仍保留原值；对比线程共享与进程隔离 | binder_proc 所代表的通信上下文；不提前等同于一份完整进程模型 |
| P02 系统调用 | 普通函数为什么不能直接执行特权操作？库函数与 syscall 区别 | strace 观察调用边界；错误码与 errno；追踪 Socket RPC 的阻塞点 | ioctl 与 BINDER_WRITE_READ 的关系 |
| P03 内核模块 | 为什么模块有 init/exit 而不是 main？谁加载和调用它？ | VM 中加载、卸载、加载失败；日志能关联到本次实验 | 驱动注册与模块/内建构建区别 |
| P04 实验环境 | 如何使驱动故障可恢复、环境可复现？ | 固定内核与配置；从干净目录启动 VM；模块 vermagic 匹配 | 固定版本 Binder 驱动的构建配置 |
| 01 IPC 动机 | Socket 已能 RPC，为什么还要研究专用驱动？ | 本地、fork 隔离、Socket 请求/回复；远端错误与连接失败不同 | BC/BR 请求回复协议，业务分发仍在用户态 |
| 02 字符设备 | 如何给进程一个受控内核入口？read/write 与 ioctl 如何取舍？ | 打开/关闭、未知命令、错误指针、长度边界；失败不遗留资源 | binder_open、binder_ioctl、每次打开的上下文 |
| 03 同步 RPC | 请求去哪儿，Server 如何等待，回复交给谁？ | 固定 Server 下排队与唤醒；无 Server、退出、信号中断；无串回复 | 进程工作队列、等待与最小事务关联 |
| 04 mmap | 接收数据为什么还要复制一次？映射换来哪些责任？ | 对照复制路径；映射权限、越界、close 后映射、耗尽与释放 | binder_mmap、binder_alloc、接收地址与 BC_FREE_BUFFER |
| 05 Parcel | 为什么不能直接发送含指针的 C struct？数据与对象如何区分？ | 字符串/整数往返；截断、对齐、恶意偏移拒绝 | libbinder Parcel 与驱动对象偏移表的职责边界 |
| 06 Transaction | 两次同时调用如何区分？完成、回复、释放是不是同一件事？ | 交错请求、重复回复、取消与退出竞争；终结恰好一次 | binder_transaction、transaction_stack、BR_TRANSACTION_COMPLETE 非业务回复 |
| 07 Node | 一个 Server 内有多个对象，如何保持对象身份？ | 两个对象同一方法返回不同结果；重复发布同一对象保持身份 | binder_node、本地 ptr/cookie 语义 |
| 08 Ref | 全局 ID 与进程私有 Handle 如何取舍？引用传递为什么需要转换？ | A→B→C 对象传递；相同 Handle 数字在不同进程意义不同；伪造拒绝 | binder_ref、BINDER_TYPE_BINDER/HANDLE 转换 |
| 09 ServiceManager | 还没有引用，如何找到第一个服务？ | 注册/查找/重复名/不存在；首个管理器的授权与访问策略 | Context Manager 与用户态 servicemanager 的分工 |
| 10 线程 | 单队列为何不够？同步等待中收到回调怎么办？ | 多 Client；A→B→A 嵌套；串行池与重入调度对比 | binder_thread、线程/进程待办、事务栈、looper 协议 |
| 11 FD | 把整数 fd 发过去，为什么不是同一个文件？ | 同号不同文件反例；真实传递；共享文件偏移；安装失败回收 | binder_fd_object、文件引用、目标 FD 安装；DMA-BUF 应用 |
| 12 生命周期 | 有引用是否意味着进程不会死？弱引用保持什么？ | 引用增减、服务退出、注册通知与死亡竞争、客户端退出 | 驱动引用协议、libbinder 对象生命周期、死亡通知 |
| 13 安全 | 可寻址是否意味着有权限？谁提供可信身份？ | 伪造 payload UID 不改变内核身份；跨 UID 拒绝；服务级授权 | 调用者凭据、LSM/Binder hooks、用户态权限判断 |
| 14 Oneway | 不等回复是否就没有成本？顺序以什么为单位？ | 慢 Server、有界队列、同对象顺序、不同对象并发、背压 | TF_ONE_WAY、Node 异步队列、异步空间限制 |
| 15 稳定性 | 哪些操作可以并行，锁与回收如何协作？ | 锁顺序审查、KASAN/lockdep、并发退出、分配失败与压力 | Binder 锁域、引用保护、延迟回收路径 |
| 16 架构 | 为何真实系统需要这些对象和边界？ | 对照实验日志定位 proc/thread/node/ref/alloc 的职责 | 固定源码版本的结构、所有权与锁保护关系 |
| 17 调用链 | 一次调用的四个协议事件如何连接起来？ | 同步调用逐跳跟踪；数据、引用、线程、释放分别追踪 | BC_TRANSACTION→BR_TRANSACTION→BC_REPLY→BR_REPLY |
| 18 复盘 | 哪些简化不能进入生产？Rust 改变和不改变什么？ | 逐项差异审计；复跑关键反例；检查所讨论实现的版本和状态 | 真实 C Binder 与选定 Rust 实现；不预设成熟度或合入状态 |

## 范围与发布

首版面向 Linux x86_64，C 驱动与用户态库。mini-binder 不兼容 Android libbinder ABI，不承诺生产安全性。设计正确性仍从首章开始要求，不能以教学为由保留已知的内存破坏。

源码阅读先固定 Linux v6.6 的 Binder 驱动；这是可定位的阅读基线，并非“所有 Android 设备实际使用的版本”。QEMU 可运行内核的具体补丁版本与配置在 M0 中锁定并实测后记录，不把未验证版本写成已支持环境。

HTML 网站采用 Markdown 内容生成，优先 MkDocs Material；等 M1 形成完整阅读路径后接入。交互可视化优先用于映射、引用转换、事务和线程调度，并与真实实验相互印证。电子书在内容稳定后导出，关键论证不能只存在于网页动画里。

Git 主线持续演进，章节发布使用不可移动标签。每次 ABI 变化记录迁移理由，链接前后 diff；修订使用新标签。当前没有发布标签，不把开发快照称为正式章节版本。
